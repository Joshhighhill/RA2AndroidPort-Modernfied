# Gap analysis 01 — Player controls and in-game UI (REAL interactive play)

Read-only audit of master @ `f9b93ba` (post P1–P10 merge), 2026-10-06.
Scope: the interactive loop `main()` → `run_menu` (main.cpp:6816) → `ShellScene`
→ `SkirmishSetupScene` / campaign scenes → `GameScene` (main.cpp:4343–5255),
`engine/input.*`, `engine/platform.*`, `engine/sidebar.*`, the sidebar/cursor
draw helpers (main.cpp:3519–3900). Every "Clone" cell was traced in the
interactive code path (event → `Input`/`GameScene` → `World` → render); nothing
is marked WORKS from a gate. Line numbers are from master at the commit above.

Original-behaviour sources: `D:\Red Alert 2\KeyboardMD.ini [Hotkey]` (the
shipped default bindings; codes are VK + 256 Shift / 512 Ctrl / 1024 Alt),
`RA2MD.INI [Options]`, and the RE docs under `docs/re/` (section numbers
cited). Items marked (RE-OPEN) still need a Ghidra confirmation — see the last
section.

Two cross-cutting facts drive many rows:

* **F1 — the scene driver eats Escape.** `run_scene_driver` returns 0 on any
  `InputEvent::Quit` *before* the scene sees it (main.cpp:3972), and
  `Platform::poll` maps `SDLK_ESCAPE` to `Quit` (platform.cpp:102). So in a
  real game Esc **terminates the process** — it never reaches `GameScene::handle`'s
  cancel chain (main.cpp:4607–4611, which the code itself calls "dormant"),
  `InGameMenu::handle`'s Quit→Resume (main.cpp:4303), or `Input::cancel_one_mode`.
  Original: `Options=27` (Esc) opens the in-game options dialog 0xB5 and the
  ESC handler `FUN_004AAC40` cancels one armed mode per press
  (repair-sell.md §C1).
* **F2 — no keyboard beyond 7 keys.** `Platform::poll` only emits `Key` for
  Backspace/Enter/Up/Down/Delete/F10/F1 (platform.cpp:104–117); everything else
  becomes `None`. `GameScene::update` additionally polls raw scancodes for
  arrows, `D`, `N` (main.cpp:4624–4627, 4661, 4673). Nothing in `[Hotkey]`
  other than `DeployObject=68` (D) exists.
* **F3 — the player unit roster is 5 types.** `GameScene` builds `ur_` from
  `load_unit_roster` = `kUnits {E1, GGI, MTNK, FV, SREF}` (main.cpp:1528–1545).
  The 12 `kRosterUnits` and 25 `kRoster2Units` tables are `[[maybe_unused]]`
  and "Called ONLY by the --demo-roster / --demo-roster2 gate" (main.cpp:1582,
  1613). Engineer, Spy, Tanya, dog, Chrono/War Miner, MCV, every naval unit,
  every aircraft and every transport are **unbuildable in real play**.
* **F4 — Android touch has no secondary button.** `SDL_FINGER*` map to
  `PointerDown/Up Left` only (platform.cpp:147–165). Every order in `Input` is
  on the **Right** button (input.cpp:507–764).

## Top 10 blockers (ordered by impact on actually playing)

1. **Esc exits the program** from anywhere (menu, lobby, mid-game, mid-placement) — `run_scene_driver` consumes `Quit` before the scene (main.cpp:3972). Every "Esc cancels X" path in the code is dead and a reflex key loses the whole session. (#1, S)
2. **A skirmish can never be won or lost** — `World` computes victory but `GameScene` only ends campaign missions (main.cpp:4694). (#2, S)
3. **Android cannot issue a single order** — touch is Left-only and all orders are Right-button; edge scroll sticks on the last touch; D/N/F10 unreachable. (#3/#4, M)
4. **Only 5 units are buildable** (E1, GGI, MTNK, FV, SREF); the other 37 roster types, including miners, engineers, transports, MCV, all naval and air, exist only in gate loaders (main.cpp:1582, 1613). Losing the free miner ends the economy. (#16, M)
5. **Choosing Soviet (or Yuri) as the human makes the game unplayable** — Allied sidebar/roster/factory lists against a Soviet base → no units ever (main.cpp:5078–5088, 4425–4426). (#36, S)
6. **No naval or aircraft production path** — four `QueueCat`s, GAWEAP-only handoff; shipyards/airfields are decorations (production.hpp:172; main.cpp:4710–4730). (#17, M)
7. **No hotkeys**: Stop, Guard, Scatter, groups, tab keys, center-base, repair/sell toggles, type-select — the `Platform` delivers 7 keys. Units cannot even be told to stop. (#10/#13, M)
8. **Build-queue semantics inverted**: left-click on a busy cameo cancels, right-click does nothing, unit queues hold one item, no hold/count. (#18, M)
9. **Nuke for everyone at frame 0** without a silo (main.cpp:11618–11624); SW cameo parked over the minimap. (#25/#26, S)
10. **No feedback layer**: no action cursors, no tooltips, EVA = "Unit lost" only, minimap non-interactive without buildings, no building selection/HP. Playable but blind. (#11/#27/#31/#39/#40, S–M)

Second tier (MAJOR, not top-10): allies attackable by right-click (#12), no building selection (#31), fixed Allied-prefix build filter (#15), strip scrolling (#38), game speed (#24).
