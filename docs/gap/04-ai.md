## Top 10 blockers (ordered)

1. **No economy in real play** — `launch_skirmish` never arms `set_economy`, so
   neither the AI nor the player harvests; the AI runs out of money after its
   first ~5 structures and then does nothing for the rest of the game
   (world.cpp:3219, main.cpp:11574 vs 15359). One-line fix, hash re-pin.
2. **AI-2 teams never enabled interactively** — `cfg.team.enabled` is only set by
   `make_ai_team_config`, which only the two AI gates call (main.cpp:9227, 9476);
   `step_ai_teams` skips every house (world.cpp:2730). The AI never trains or
   orders a unit; the player cannot lose a skirmish. Regressed in `f77e68e`.
3. **AI-2 script opcode table is wrong** — `classify_op` uses numbers that do not
   match the binary's 65-entry executor at `0x6E94E4` (c13/c14 logs; campaign.md
   §7). Once (2) is wired the stock scripts (1/2/3/4/46/47/58 heavily used) are
   skipped or misread. The P10 executor already has the correct table.
4. **No MCV / `BaseUnit` start** — no MCV type exists; every base is pre-spawned
   instantly, the AI never deploys, `UnitCount` semantics and `MCVRedeploys`
   are unreachable.
5. **AI difficulty is inverted/ineffective** — lobby Easy gets the `[Easy]`
   DifficultyClass bonuses that the original gives the hardest AI (ai-trigger.md
   §5 confirms index 0 = hardest); no Armor/ROF/Firepower handicap is applied
   to AI units at all.
6. **Allied-side AI slots build a Soviet base** — `make_ai_config` and
   `make_ai_team_config` are Soviet-only; `can_start` has no Owner check.
7. **AI never repairs** (P1 cut) — base damage is permanent; combined with no
   rebuild money (1) the AI base only ever decays.
8. **AI never fires or builds superweapons** — it is granted a Nuke that charges
   forever; `step_superweapon` only ticks.
9. **AI-3 gate `--demo-ai-trigger` DIFFs on master** — the trigger engine is
   both unreachable interactively and no longer byte-identical after the merge.
10. **Campaign enemy houses have no AI** — no base build-out, production or AI
    triggers; only pre-placed objects, map teams and hunt.

## Resolution of the script-action numbering conflict

- Binary (P10 hunt, `D:\ra2-re\p10out\c13.log:29-33`): the TeamClass script
  executor does `CMP EAX,0x40 / JA <no-op> / JMP dword ptr [EAX*4 + 0x6e94e4]`,
  i.e. actions 0..64 only; `c14.log` dumps each handler (idx 49 sets
  team+0x80 and team+0x84 = the success/step-complete flags, matching both
  docs; idx 12 is `PUSH 1 → set global`, idx 3 → move-to-waypoint helper).
  Anchors agree with ModEnc/YRpp `TeamMissionType` at every read
  (campaign.md §7).
- `ai-team.md` §3's "FUN_006e30d0 enumerates ~90 valid actions up to 0x90" is
  a different switch: `FUN_006e30d0` is called from `FUN_006dc870`, which the P9
  map-trigger hunt dumped under the `actpre` tag (`p9out/actpre_006dc870.c:17`,
  `scripts/p9_trig3.py:29` range `0x6dc800-0x6dd000 "actpre"`) — the map
  `[Actions]` (TAction) argument classifier, whose numbering does run past 140.
  The AI-2 table (ai_team.hpp:58-71) must be replaced by the 0..64 table.
- `ai-team.md` §3's "stock-used actions" list (0,5,6,8,9,0xb,0xc,0xe,0x15,…) also
  does not match the real file: the extracted `aimd.ini` uses 1×66, 2×60,
  3×26, 4×24, 46×45, 47×24, 58×49, none of which the doc lists as stock-used.
