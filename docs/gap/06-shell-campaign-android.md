# Gap analysis 06 — game shell, session flow, campaign, Android

Read-only audit of master `f9b93ba` (2026-10-06). Scope: `run_menu` / `ShellScene`
(`MainMenuScene`), `SkirmishSetupScene`, `GameScene` session flow, `CampaignLoadScene` /
`CampaignResultScene` / `CampaignRuntime`, map triggers **in interactive campaign play**,
the Load/Save/Delete dialog, Options, and the Android app. Every "Clone in REAL play"
cell was traced through the interactive path (`main()` → `run_menu` → scenes), not
through a `--demo-*` gate. Original behaviour is cited from `docs/re/*.md`; nothing
below needed a new Ghidra run (open questions are listed at the end). The gate run
was still in progress during this audit (`gate_results.txt` had no `ALL DONE`), so no
`ra2engine.exe` / Gradle run was made; everything is static evidence plus a data census
of the 24 RA2 mission maps (extracted with `build/ra2extract.exe`, script and output in
the session scratchpad `gapmaps/census.py` / `census.txt`).

Status legend: WORKS / GATE-ONLY / PARTIAL / WRONG / BROKEN / MISSING.
Severity: BLOCKER (game unplayable or core loop broken) / MAJOR / MINOR.
